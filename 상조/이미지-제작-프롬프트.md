# 상조 페이지 교체용 이미지 제작 안내 (내부용)

대상: `상조/상조-리디자인.html` · 공개 사이트에서 제외되는 문서입니다(`_config.yml`의 `exclude`).

## 현재 상태

- 힉스필드 연결: **MCP 커넥터**(API 키 방식 아님). 요금제 free, 크레딧 10. 이 커넥터에는 **생성 도구가 없어** 조회·잔액 확인만 가능합니다.
- 모델별 생성 비용은 조회되지 않아, 이번 작업에서는 **생성 요청을 하지 않았습니다.** (실제 생성 비용 0)
- 현재 화면은 아래 SVG·CSS 그래픽으로 만든 임시 시안입니다.
  - 첫 화면: 보험 페이지의 기존 3D 상담사 이미지(720px WebP, 32KB로 압축) + SVG 리본
  - 서비스 아이콘 4종: 인라인 SVG
  - 장례 형태 배치도 2종: 인라인 SVG
  - 구성 그림 12종(접이식 안): 인라인 SVG, 임시 시안

## 제작 원칙

- 이미지 안에 글자를 넣지 않습니다. 제목·설명은 모두 웹 텍스트입니다.
- 비밀키를 브라우저 코드에 넣지 않습니다. 생성은 제작 단계에서 한 번만 하고, 결과 파일을 `상조/images/`에 저장해 사용합니다(페이지를 열 때마다 생성하지 않음).
- 저장 형식: WebP, 아래 권장 크기. 첫 화면 이미지만 즉시 로딩하고 나머지는 `loading="lazy"`로 지연 로딩합니다.
- 색상: 아이보리 `#fbf8f1`, 깊은 청록 `#0a4f49`, 민트 `#3ed3b5`.

- 항목: 장례 절차 안내 / 입관 지원 / 장례용품 / 장의차량
- 권장 비율/크기: 각 1:1, 원본 800×800 → 웹용 224×224 WebP (투명 배경)
- 저장 이름: `images/svc-guide.webp`, `svc-support.webp`, `svc-goods.webp`, `svc-car.webp`
- 4종을 같은 시드·같은 프롬프트 구조로 한 번에 만들어 색·재질·시점·조명을 통일합니다.

공통 프롬프트(항목 부분만 바꿈):

## 4. 교체 방법 (개발자용)

1. 위 파일을 `상조/images/`에 저장합니다.
2. 첫 화면: `상조-리디자인.html`의 `.hero-art img`의 `src`를 `images/hero-mascot.webp`로 바꾸고 `width`/`height`를 실제 크기에 맞춥니다(`fetchpriority="high"` 유지).
3. 서비스 아이콘·장례 형태 이미지: 해당 위치의 SVG를 `<img src="images/..." alt="..." width="..." height="..." loading="lazy" decoding="async">`로 교체합니다.
4. 용량 점검: 첫 화면 이미지 80KB 이하, 아이콘 각 20KB 이하, 장례 형태 이미지 각 60KB 이하를 목표로 합니다.

## 5. 생성 전 확인할 것

- 사용할 모델(힉스필드 모델 목록에는 GPT Image 2, Nano Banana Pro, Seedream 4.5 등이 있음)과 이미지별 예상 비용·총비용을 확인한 뒤 진행합니다.
- 무료·무제한 혜택이 MCP/API 생성에도 적용된다고 가정하지 않습니다.
